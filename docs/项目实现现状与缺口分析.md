- 修订日期：2026-11-17。最初快照是 2026-11-15 的只读核对；本节之后按当天已经落地的代码改写。
- 分析对象：当前仓库的 Go 源码、SQL 迁移、配置、脚本、测试及实施文档。
- 分析方式：核对当前代码。同日在 `go1.27.3 darwin/arm64` 上运行了默认 `go test ./...`，并在本地 `iot-dev` 上运行了带 `integration` 标签的回归。没有连接公网 Broker、真实设备、真实 APP 或媒体服务。
- 本文是当前代码和这次本地验证的快照，不替代人工验收，也不改变 2026-11-13 的 P1、P2 结论，不表示 P3 已经开始。
- 历史动作与验收以 [实施进度](实施进度.md) 为准；接口示例见 [控制平面请求集](控制平面请求集.md)。

**总体定位：项目已经实现本地 MQTT 设备业务闭环，以及使用测试替身的 RTC 控制平面；尚未实现真实音视频业务和完整生产交付。**

| 层次 | 当前状态 | 不能据此推导的结论 |
|---|---|---|
| 设备业务 | 设备登记、权限、MQTT 接入、属性存储、异步命令及回执已有实际代码；服务连接使用持久会话和收件箱 | 不代表已完成真实设备和 APP 验收，或故障下端到端不丢消息 |

未配置依赖时只提供基础骨架；设备业务 API 的挂载需要 Store。基础进程存活不等于业务依赖已可用，见 `internal/app/runtime.go`。

### 2.2 用户、权限与设备管理

- 用户以用户名和密码登录，密码使用 bcrypt；访问令牌由服务端生成，数据库保存摘要和有效期。
- 后续请求通过 Bearer Token 取得当前身份，不信任请求体自行声明的用户 ID。
- 支持平台管理员和设备级 `manage`、`view`、`call`、`ticket` 授权。
- 支持设备登记、列表、能力与当前属性查询，以及授权、启用、禁用和吊销接入资格。
- 登录和命令创建使用 Redis 限流；Redis 失败时拒绝相关操作。
- 已有部分审计记录，但不是覆盖所有状态变化的完整审计系统。

主要代码：`internal/api/httpapi/server.go`、`internal/store/users.go`、`internal/store/devices.go`。

### 2.3 MQTT 设备业务

| 能力 | 已有行为 |
|---|---|
| 接入认证 | Hook 校验共享设备口令、合法 ClientID、设备登记、启用和吊销状态 |
| Topic ACL | 设备只能发布自己的 report、set_reply、status，并订阅自己的 property/set；拒绝越权和通配访问 |
| 禁用踢线 | 更新数据库后调用 EMQX 管理 API 尝试断开设备 |
| 属性上报 | 校验协议、功能点与类型，写当前属性和历史 |
| 去重 | 按租户、设备、msgId 和原始载荷摘要去重；同 msgId 的不同载荷保留 |
| 异步命令 | 命令先入库再发布。截止后超时；`uncertain` 不自动重发，设备回执或人工重试、关闭可以收敛。禁用和吊销会取消不再可发的命令 |
| 会话在线 | 消费 EMQX 系统连接事件，区分 MQTT 在线和设备自报状态，过滤部分旧会话断线事件 |
| 入站恢复 | 服务连接是持久会话。队列上限 256 条，成功落库后才确认；收件箱可在下次连接前恢复。持续失败会隔离，依赖不可用时不记成毒消息 |
| 多实例基础 | 共享订阅与数据库任务领取，具有本地双实例测试用例。另一个活着的实例可以取走新消息；本客户端 ID 只恢复自己未确认的消息 |

主要代码：`internal/bridge/`、`internal/mqttmsg/`、`internal/presence/`、`internal/store/commands.go`、`internal/store/messages.go`。

当前协议面向已有中控固件，功能点包括温湿度和六路布尔开关，不是通用设备协议引擎。命令的 accepted 表示收到设备成功回执，不等于已经独立核验物理状态达到目标值。本地 EMQX 渲染关闭认证和授权的节点缓存，禁用或依赖故障后的下一次连接会重新询问钩子。设备侧连接仍然使用 clean session。

### 2.4 RTC 数据库控制平面

| 能力 | 已有行为 |
|---|---|
| Ticket | 摘要落库、有效期、当前版本、换票与旧票限制 |
| Viewer | 独立 viewer_id、客户端幂等、心跳和退出。JOINING 与 ACTIVE 都只在心跳宽限内占用 |
| Session | 按设备、通道、码流、清晰度建账和复用。启动阶段有振铃超时 |
| 状态控制 | 会话状态机、generation 轮次、version 更新与独立流占用。清理不要求设备仍然启用 |
| 主通话 | 设备级唯一占用。被叫必须是另一名有 call 权限的用户；只有被叫可接听或拒绝。接通有超时，无媒体的 CONNECTED 会结束 |
| 后台任务 | MySQL 保存任务，SKIP LOCKED 领取。每次领取递增 lease_token，完成和重试必须匹配所有者和令牌 |
| 内部事件 | 事件去重、部分资源映射。媒体和 call.connected 都要匹配当前会话与代数 |

主要代码：`internal/store/rtc.go`、`internal/rtc/state.go`、`internal/api/httpapi/rtc.go`。

观看响应明确是 `provider=test`、`connectable=false`。TestProvider 的房间只是 `test:` 标识，删除房间和移除参与者没有外部副作用。见 `internal/media/provider.go`。

## 4. 尚未形成的完整业务

### 4.1 真实视频观看

仍需设备视频采集和编码、实际发布能力、真实流控制协议、正式媒体服务、可连接媒体凭证、播放客户端及首帧和失败反馈。

目前没有证据表明这些已经接通。现有控制事件把会话推进到 ACTIVE，不能替代真实可播放验证。

### 4.2 真实双向通话

仍需设备音频硬件和软件能力、被叫与邀请协议、双方媒体身份与凭证、双向收发、音频路由、建连超时、断线重连、挂断清理及私有轨道隔离。

普通 Viewer 不得订阅通话 APP 的私有上行，这需要真实 Provider 的权限能力和端到端负向测试，而非仅靠业务角色名称。

### 4.3 网络、客户端与生产环境

- 未完成目标家庭网络、移动网络、网络切换和强制 TURN 验证。
- 仓库没有完整 APP 或 Web 管理端；如目标包括完整产品，需要独立交付客户端工程。
- 当前依赖配置限制在本地，并固定部分账号、库名和管理端口，不是替换环境变量即可投入生产。见 `internal/config/deps.go`。
- 业务监听已经不再提供 `/internal/`，测试控制入口默认关闭。这仍不是生产网络隔离。
- 尚缺生产拓扑、高可用、TLS、密钥轮换、容量长稳、故障恢复、备份恢复、监控告警及灰度交付实证。
- 文档中的 10,000 台设备是容量目标，不是当前已经证明的承载能力，也不等于同数量的视频能力。

### 已确定的换票策略

根据实施进度里的「换票后的存量连接」，策略已经确定，不应再次列为完全未决：

- 旧票据不能再授权新的观看、续签或通话。
- 已加入观看者和已建立通话留到本轮结束，结束边界包括退出、超时、通话终态或既有关流规则。
- 禁用设备拒绝新业务并尝试踢掉 MQTT，但不会因此删除现有 Viewer/Call 行。
- 当前没有真实媒体参与者移除，也没有独立安全事件入口。
