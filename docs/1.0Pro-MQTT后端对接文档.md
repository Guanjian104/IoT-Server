| 项 | 内容 |
|---|---|
| 产品 | 宠智灵智能项圈 1.0pro |
| 模组 | 移远 EG810MCN_LA（QuecOpen / ThreadX） |
| 现行固件 | 1.7.31（以设备上线报文 `fw` 为准） |
| 协议版本 | MQTT IoT V1.2 |

## 1. 连接

固件宏 `PETCOLLAR_MQTT_SERVER_PRIVATE=1`。服务器由该宏选择（见 `petcollar_config.h`）。

| 项 | 值 |
|---|---|
| URL | `mqtt://120.25.100.77:11884` |
| Host | `120.25.100.77` |
| Port | `11884` |
| TLS | 否 |
| MQTT 版本 | 3.1.1 |
| Username | `root` |
| Password | 见固件 `petcollar_config.h` 的 `PETCOLLAR_EMQX_PASSWORD` |
| ClientId | Wi-Fi STA MAC，12 位小写十六进制、不带冒号 |
| KeepAlive | 90 秒。设备大约每 45 秒发一次 PINGREQ |
| Clean Session | 1 |
| Will | 无 |
| QoS | 上下行均为 1 |
| Retained | 只有上线报文为 1，其余为 0 |

示例：MAC `90:30:D6:CB:0D:6D` → ClientId `9030d6cb0d6d`。

连接失败时设备每 10 秒重试。Broker 回 CONNACK `0x05`（未授权）时同样按失败重试，不换 ClientId。

备用 EMQX Cloud（`PETCOLLAR_MQTT_SERVER_PRIVATE=0`）不在当前烧录路径里。切过去之后 Host 为 `v963899a.ala.dedicated.aliyun.emqxcloud.cn:8883`（TLS），账号为 `PETCOLLAR_DEVICE_ID` / `PETCOLLAR_DEVICE_SECRET`。前缀改为 `petcollar_1pro`，`{mac}` 保持原样大小写。业务主题是 `telemetry`，在线主题是 `status`（retained）。

| Topic | 方向 |
|---|---|
| `petcollar_1pro/{mac}/cmd` | 云 → 设备 |
| `petcollar_1pro/{mac}/telemetry` | 设备 → 云（cmd_result / location / DP） |
| `petcollar_1pro/{mac}/status` | 设备 → 云（retained 在线） |

## 2. Topic

`{mac}` 与 ClientId 相同，私有服为小写。

| Topic | 方向 | 说明 |
|---|---|---|
| `pet/collar/1_0pro/{mac}/cmd` | 云 → 设备 | 控制命令。不要带 `msgId` |
| `pet/collar/1_0pro/{mac}/state` | 设备 → 云 | 上线、命令结果、定位、姿态、活动时长 |
| `pet/collar/1_0pro/{mac}/audio` | 双向 | 录音上传、预设音下发。不进 `state` |

`2_0_test` 固件使用同一套报文，只把路径中的 `1_0pro` 换成 `2_0_test`。一台设备只登记其中一个代次。

后端订阅 `pet/collar/1_0pro/+/state` 和 `pet/collar/1_0pro/+/audio`。命令发到 `.../cmd`，预设音内容发到 `.../audio`。

ACL：

- 设备只能访问自己的三个主题，不能订另一代次，也不能订 `pet/collar/#`。
- 后端可以发布 `+/cmd` 与 `+/audio`，订阅 `+/state` 与 `+/audio`。
- 登记为 `watch` 的连接可以订阅 `pet/collar/+/+/state`，或把其中一段写成具体代次、具体设备号，并可以向具体设备的 `cmd` 发布指令。它不能订 `cmd`，也不能订 `pet/collar/#`。

在线判定：

1. `.../state` 上 retained 的 `{"online":true,...}`。
2. 之后任意已收下的 `state` 或 `audio` 上行。只连上 MQTT、没有这些报文，不算在线。
3. 超过 180 秒没有任何 `state` 上行则判离线。KeepAlive 是 90 秒，180 秒大约是连续两次心跳没到。

1.7.31 的发送队列：离线时设备缓存最多 8 条、每条小于 256 字节的 `state` 报文，重连后补发。缓存满了丢掉最旧的一条。在线时另有 8 条待发队列，按入队顺序发送。队列满了丢掉最旧的一条，不会用新报文盖掉尚未发送的 `cmd_result`。`audio` 不缓存。

1.7.28 没有这条在线队列。离线缓存同样最多 8 条，但同一时刻只有一个待发槽，新的 `state` 报文会盖掉还没发出去的那条。

下行命令不缓存。发出后 15 秒内没有对应 `cmd_result`，按失败处理。

## 3. 上线

主题 `.../state`，QoS 1，retained=1。

```json
{"online":true,"fw":"1.7.31","hw":"1.0PRO-M","ts":1762930000}
```

| 字段 | 说明 |
|---|---|
| online | 固定 `true` |
| fw | 固件版本 |
| hw | 中板为 `1.0PRO-M`，小板为 `1.0PRO-S` |
| ts | 设备 Unix 秒 |

没有单独的离线报文。会话断开，或超过第 2 节的 180 秒没有 `state` 上行，即离线。

## 4. 下行命令

发到 `.../cmd`。直接控制，无 `msgId`。`on` 省略时按 `true`。

```json
{"cmd":"mic_record","on":true,"params":{"duration_s":10}}
```

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| cmd | string | 是 | 见下表 |
| on | bool | 多数指令 | `true` 开 / `false` 关；一次性指令可省略，省略按 `true` |
| params | object | 视指令 | 参数表 |
| ts | number | 否 | Unix 秒，设备可忽略 |

未知 `cmd` 回 `failed`，`code=-1`。

### 4.1 命令表

| cmd | 作用 | 设备行为 |
|---|---|---|
| `find_light` | 近处寻宠闪灯 | PIN21，高电平点亮。`freq_hz>=3` 快闪（约 166 ms），否则慢闪（500 ms）。`duration_min` 钳到 1–60，默认 1。`color` 忽略。关灯回 `success`，到时回 `ended` |
| `buzzer` | 扬声器寻宠提示音 | 没有独立蜂鸣器。`tone_hz` 只认 2000 或 3000，其它当 2000。`count` 钳到 1–60，默认 10。每声约 120 ms，间隔约 280 ms |
| `gps_oneshot` | 立刻定位一次 | 不进入持续周期。先回 `accepted`，定位窗口结束后再回 `success` 或 `failed`/`-30`，并带一条 `location`（`reason=oneshot`） |
| `find_mode` | 走失时高频定位 | `duration_min` 1–300，默认 5。`interval_s` 2–30，默认 5。开启时立刻要一个点，之后按间隔上报 `reason=find`。到时或 `on:false` 退出，并同步 `mode_state` |
| `trip_track` | 出行周期轨迹 | `interval_min` 1–60，默认 5。开和关各立刻要一次 `reason=oneshot`。周期点是 `reason=trip`，不能替代开、关时的即时定位 |
| `activate` | 激活确认 | 立刻回 `success`，不额外开外设 |
| `mic_record` | 按时长录音 | `duration_s` 1–60，默认 10。音频走 `audio` 主题。录音结束不等于云端分析完成 |
| `speaker_play` | 播放云端下发的 PCM | 先在 `cmd` 里打开播放，再把音频发到 `audio`。`file` 只作业务标记，设备不按文件名选曲 |
| `voice_call` | WHIP 双向语音 | `whip_url`、`token` 必填。`duration_min` 1–60，默认 15。媒体走本进程的 WebRTC SFU |

寻宠和出行同时开时，只按寻宠间隔上报。寻宠结束后若出行仍开，恢复出行间隔。

未充电且电量不超过 10% 时，`voice_call`、`mic_record`、`speaker_play`、`buzzer`、`find_light` 的开启被拒绝，`code=-12`。充电且电量回到 15% 以上后解除。

`mic_record`、`speaker_play`、`buzzer` 与通话互斥。资源被占用时回 `busy`，`code=-11`。`voice_call` 开启时若已有录音、播放或蜂鸣，同样 `busy`。`voice_call` 不排队抢占其它音频。

| 编号 | cmd | 功能 |
|---|---|---|
| CMD-01 | `find_light` | LED 闪灯辅助寻宠 |
| CMD-02 | `buzzer` | 扬声器响铃寻宠 |
| CMD-03 | `gps_oneshot` | 立刻上报一次 GPS |
| CMD-04 | `find_mode` | 走失高频持续定位 |
| CMD-05 | `trip_track` | 出行周期轨迹定位 |
| CMD-06 | `activate` | 激活确认 |
| CMD-07 | `mic_record` | 按时长录音 |
| CMD-08 | `speaker_play` | 播放云端 PCM |
| CMD-09 | `voice_call` | WHIP 双向语音 |

### 4.2 录音

```json
{"cmd":"mic_record","on":true,"params":{"duration_s":10}}
```

停止：

```json
{"cmd":"mic_record","on":false}
```

`state` 上先回 `accepted`。到时回 `ended`。手动停止回 `success`。麦克风打不开回 `failed`，`code=-20`。

分片在 `.../audio`，单条 JSON 小于 512 字节。PCM 为 8 kHz、单声道、16 位小端，每片原始数据 192 字节，`data` 为 base64。

```json
{"type":"mic","ts":1760580001,"seq":0,"last":0,"fmt":"pcm16le","rate":8000,"data":"<base64>"}
```

`last=1` 是最后一片。录音结束不等于云端分析完成。

### 4.3 预设音播放

先发命令：

```json
{"cmd":"speaker_play","on":true,"params":{"file":"calm"}}
```

设备回 `accepted` 后，把 PCM 发到同一设备的 `.../audio`：

```json
{"type":"preset","file":"calm","seq":0,"last":1,"fmt":"pcm16le","rate":8000,"data":"<base64>"}
```

必须带 `"type":"preset"`。`"last":1` 表示播完，设备在 `state` 回 `speaker_play` / `ended`。`on:false` 打断并回 `success`。打开播放失败回 `failed`，`code=-20`。

### 4.4 通话

```json
{"cmd":"voice_call","on":true,"params":{"whip_url":"http://120.25.100.77:18196/whip/pion-9030d6cb0d6d","token":"<Bearer>","duration_min":15}}
```

通话过程只走 `cmd_result`，`cmd` 固定为 `voice_call`。不再上报 `agora_state`。

`accepted` 在开始 WHIP 之前入队。缺 `whip_url` 为 `-21`，缺 `token` 为 `-22`，这两条没有 `accepted`。

接通顺序：

1. `accepted`
2. `joining`：正在 POST WHIP、做 STUN/DTLS
3. `in_call`：SRTP 已建立
4. `ended`：`on:false` 或到达 `duration_min`

失败顺序：`accepted`、`joining`、`failed`。`code` 是设备错误号。WHIP 有 HTTP 响应时同时带 `http`（例如 400）和服务器正文 `detail`（最多 40 个可见字符）。连接没到 HTTP 时 `code` 直接是传输错误（`-10` 到 `-17`），没有 `http`。失败后不再另发 `ended`。

```json
{"ts":1795578607,"type":"cmd_result","cmd":"voice_call","result":"failed","code":-27,"http":400,"detail":"bad request"}
```

常见 `code`：`-23` SDP、`-24` UDP、`-25` 会话冲突、`-26` 鉴权、`-27` WHIP 非 201、`-28` 应答 SDP、`-29` 地址、`-30` 打开音频、`-40` 射频。

挂断：

```json
{"cmd":"voice_call","on":false}
```

设备只回一条 `ended`。到 `duration_min` 也会自己挂断并回 `ended`。旧固件上的 `agora_state` 可以忽略。

1.7.28 没有 `joining`、`in_call`，也没有 `http`、`detail`。当时 `accepted` 只表示设备收下了参数并开始 WHIP；建链失败直接 `failed`，`code` 为设备返回值；挂断或到时回 `ended`。

通话期间定位窗口暂停。Answer 若是 `recvonly`，项圈只上行，听不到对端。对端要出声，Answer 需要 `sendrecv` 或 `sendonly`，并发送 PCMA/8000 RTP。

## 5. 上行 `state`

除上线报文外，retained=0。

### 5.1 `cmd_result`

```json
{"ts":1760580001,"type":"cmd_result","cmd":"mic_record","result":"accepted","code":0}
```

| result | 含义 |
|---|---|
| `accepted` | 持续任务已开始 |
| `joining` | 仅 `voice_call`：正在建立 WHIP/DTLS。1.7.28 没有这一档 |
| `in_call` | 仅 `voice_call`：媒体已接通。1.7.28 没有这一档 |
| `success` | 一次性操作完成，或用户主动关掉 |
| `failed` | 失败，看 `code` |
| `ended` | 定时结束，或通话被挂断、到时 |
| `busy` | 音频被占用 |

| code | 含义 |
|---|---|
| 0 | 成功 |
| -1 | 未知命令 |
| -11 | 音频忙 |
| -12 | 低电量保护，拒绝开启 |
| -13 | 闪光灯脚未分配（中板 1.7.28 不应出现） |
| -20 | 麦克风、扬声器或蜂鸣打开失败 |
| -21 | 通话缺少 `whip_url` |
| -22 | 通话缺少 `token` |
| -23 | 通话 SDP |
| -24 | 通话 UDP |
| -25 | 通话会话冲突 |
| -26 | 通话鉴权 |
| -27 | WHIP 非 201 |
| -28 | 应答 SDP |
| -29 | 通话地址 |
| -30 | 即时定位没有有效点；通话里也可表示打开音频失败 |
| -40 | 通话射频 |

`-10` 到 `-17` 在通话里表示还没到 HTTP 的传输错误。建链失败且有 HTTP 响应时，再带 `http` 和 `detail`。

### 5.2 `location`

```json
{"ts":1760580002,"type":"location","reason":"schedule","lat":22.5432100,"lon":113.9400000,"sats":8,"valid":true}
```

| reason | 何时出现 |
|---|---|
| `oneshot` | `gps_oneshot`，以及出行开、关时各一次 |
| `find` | 寻宠模式周期点 |
| `trip` | 出行模式周期点 |
| `schedule` | 空闲时约每 5 分钟开一次定位窗。电量保护中改为约 15 分钟 |
| `move` | 连续非静止约 50 秒后开一次定位窗 |

定位窗最长约 45 秒。没有有效星时仍可能上报 `valid=false`，经纬度为 0。天线开路时 NMEA 为 `ANTENNA OPEN`，不要把 `valid=false` 写成轨迹点。通话期间不打开定位窗。

`gps_oneshot` 的 `cmd_result` 在定位报文之后另发：有效为 `success`，无效为 `failed`/`-30`。

### 5.3 `mode_state`

寻宠或出行开关变化时发送，用来同步是否真正开启以及剩余时间。

```json
{"ts":1760580003,"type":"mode_state","find_mode":true,"trip_track":false,"find_remain_s":280,"trip_interval_s":300}
```

`find_remain_s` 仅在寻宠开启时有意义。`trip_interval_s` 是当前出行间隔，单位秒。

### 5.4 姿态与电量

姿态变化立刻发一条。连续 60 秒姿态不变，再发一条，当作心跳。没有单独的 `type=battery`。

```json
{"msgId":"pet12","ts":1760580004,"data":{"pet_action":"static","pct":99,"chg":1}}
```

| 字段 | 说明 |
|---|---|
| pet_action | `static` / `walking` / `running` |
| pct | 0–100。由电池电压线性换算：3300 mV 为 0，4200 mV 为 100。不是电量计 |
| chg | 1 正在充电，0 否。来自 PIN32 低电平，且 PIN33 未报充满 |

这条报文在姿态不变时最多 60 秒更新一次电量。USB 供电、未接电池时 `pct` 会在高位跳动，不要当成真实电量。

### 5.5 `activity`

只跟在 60 秒姿态心跳后面，姿态刚变化时不发。单位是秒，自本次开机累计。

```json
{"ts":1760580064,"type":"activity","state":"static","static_s":300,"walk_s":42,"run_s":0}
```

`state` 与该次心跳的 `pet_action` 相同。

1.7.31 起通话不再发送 `agora_state`。建链失败的 `cmd_result` 带 `code`，有 HTTP 响应时再带 `http` 和 `detail`。旧固件若仍发 `data.agora_state` 或 `type=wifi_scan`，丢弃即可。

## 6. 设备本地行为（无 MQTT）

这些状态不上报，后端不要等对应报文。

| 现象 | 条件 |
|---|---|
| 绿灯 PIN30 | PIN33 为低（充满）时亮 |
| 红灯 PIN31 | PIN32 为低且未充满时亮 |
| 闪光灯 PIN21 | 仅 `find_light` 期间闪 |
| PIN25 | 开机后拉高，放开 USB 对开机键的拉低 |

## 7. 跨指令规则

1. **出行 + 即时定位**：`trip_track` 开、关各触发一次 `reason=oneshot`。周期点不能替代这两次。
2. **寻宠优先于出行**：同时开启时按寻宠间隔上报。寻宠结束后若出行仍开，恢复出行间隔。
3. **音频互斥**（`buzzer` / `mic_record` / `speaker_play` / `voice_call`）：占用时回 `busy`，`code=-11`，不排队。
4. **低电量**：未充电且电量不超过 10% 时，拒绝开启上述音频指令和 `find_light`，`code=-12`。充电且电量回到 15% 以上后解除。低电量保护由设备执行，后端展示即可。
5. **命令不缓存**：设备离线时丢掉下行命令。平台 15 秒内没有对应 `cmd_result`，按失败处理。
6. **持续任务结束**：用户关闭、到时、失败都要有终态回执。App 看到 `ended`、`success` 或 `failed` 后，不再显示进行中。

## 8. 后端处理顺序

1. 用 `{mac}` 建档，并保存最近一次 `fw`、`hw`。
2. retained `online=true` 标记在线。之后用已收下的 `state` / `audio` 续租，超过 180 秒没有 `state` 则标离线。
3. `cmd_result` 按 `cmd` 结案。15 秒无回执算失败。
4. `location` 只在 `valid=true` 时入库。`reason` 用于区分即时、寻宠、出行、定时和移动触发。
5. `pet_action` 更新姿态，并用同一条里的 `pct`、`chg` 更新电量。
6. 订阅 `audio`。`type=mic` 按 `seq` 拼 PCM，`last=1` 结束。给项圈播声音时，先发 `speaker_play`，等 `accepted`，再按 `type=preset` 推流。
7. 通话只看 `cmd_result`：`accepted` → `joining` → `in_call`，结束是 `ended`。建链失败是 `failed`，用 `code`，有 HTTP 响应时再看 `http` 和 `detail`。不要等 `agora_state`。Answer 要能向项圈发音频时使用 `sendrecv`。

## 9. 常用示例

立刻定位：

```json
{"cmd":"gps_oneshot","on":true}
```

开始出行，每 5 分钟一个点：

```json
{"cmd":"trip_track","on":true,"params":{"interval_min":5}}
```

寻宠 5 分钟，每 5 秒一个点：

```json
{"cmd":"find_mode","on":true,"params":{"duration_min":5,"interval_s":5}}
```

结束出行、挂断通话：

```json
{"cmd":"trip_track","on":false}
```

```json
{"cmd":"voice_call","on":false}
```
